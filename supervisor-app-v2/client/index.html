Custom MCP Server on Databricks Apps

Host your own MCP server with custom tools, governed by AI Gateway and accessible to any Supervisor agent.

What is this? You write Python functions decorated with @mcp.tool(), deploy them as a Databricks App, and they become tools that any Supervisor Agent can discover and call. The MCP server exposes tools via the Streamable HTTP transport.

How It Works

1

Write MCP Tools

Use the FastMCP framework. Each tool is a Python function with a docstring that the LLM reads to decide when to call it.

2

Deploy as Databricks App

Push your code with databricks apps deploy. The app runs on managed compute with authentication built in.

3

Register as Supervisor Tool

Add {"type": "app", "app": {"name": "your-app"}} to the Supervisor's tools list. That's it.

Example Code

app.py (MCP Server) from mcp.server.fastmcp import FastMCP mcp = FastMCP("ops-tools") @mcp.tool() def get_system_metrics(service_name: str) -> str: """Get real-time system metrics for a service. Returns CPU, memory, latency, and error rate.""" # Your custom logic here - call Prometheus, Datadog, etc. metrics = fetch_metrics_from_monitoring(service_name) return json.dumps(metrics) @mcp.tool() def create_incident_ticket(title: str, severity: str) -> str: """Create an incident ticket in the ops system.""" ticket = create_in_pagerduty(title, severity) return json.dumps(ticket)

Custom Agent on Databricks Apps

Deploy specialized agents that the Supervisor can delegate to for complex analytical tasks.

Why this matters: Instead of giving the Supervisor all the logic, you can build focused sub-agents (e.g., data analyst, compliance checker, code reviewer) and the Supervisor delegates to them. Each agent can have its own model, tools, and context.

Example Code

app.py (Custom Agent) from fastapi import FastAPI, Request app = FastAPI() @app.post("/chat") async def chat(request: Request): body = await request.json() question = body["messages"][-1]["content"] # Your specialized analysis logic analysis = analyze_operational_data(question) return {"choices": [{"message": { "role": "assistant", "content": analysis }}]}

External MCP Servers with U2M Auth

Securely connect third-party MCP servers with per-user OAuth authentication.

Per-User Auth (U2M): Each user authenticates with their own credentials. When a Supervisor Agent calls a GitHub MCP tool, it uses your GitHub token, not a shared service account. This means results are personalized and access is properly scoped.

How It Works

1

Create Unity Catalog Connection

Catalog Explorer > Connections > Create HTTP Connection > Enable "Is MCP connection" > Configure OAuth U2M.

2

Grant Access

Grant USE CONNECTION to users who need the tools. Unity Catalog governs access.

3

Add to Supervisor

Reference it as {"type": "uc_connection", "uc_connection": {"name": "github_mcp"}}.

Supervisor API vs Agent Bricks Supervisor Agent

Two approaches to multi-agent orchestration - choose based on your customer's needs.

API-First Supervisor API

For developers building custom agent systems. Full model choice, API-first, nothing persisted.

response = client.responses.create( model="your-choice", tools=[...], instructions="..." )

Low-Code Agent Bricks Supervisor

For analysts & business users. UI-driven, config persisted, model abstracted away.

Create in Agent Bricks console > Add tools > Add examples & guidelines > Deploy.

Feature Comparison

FeatureSupervisor APIAgent Bricks Supervisor
InterfaceREST API / SDKUI Console + API
Model ChoiceYou choose (Claude, GPT-5, etc.)Databricks chooses (abstracted)
ConfigurationIn code (stateless)Persisted (saved in platform)
Quality TuningVia instructions parameterExamples + Guidelines UI
Background ModeYes (30 min max, poll for results)No
TracingUnity Catalog tracesBuilt-in MLflow traces
PricingAI Gateway usage + tool costsDBU per step (~$0.01-$0.44)
Best ForCustom apps, CI/CD pipelines, programmatic agentsQuick prototyping, business-user-facing agents
Key Insight: Both share the same tool types now. The difference is in how you build - Supervisor API gives you full control via code, while Agent Bricks Supervisor gives you a managed experience. Over time, these are expected to converge.

When to Recommend Each

Use Supervisor API when:

  • Customer needs specific model choice
  • Building agents programmatically (CI/CD)
  • Need background/async execution
  • Embedding into existing apps
  • Want full control over orchestration

Use Agent Bricks Supervisor when:

  • Quick prototyping / POC
  • Business users managing the agent
  • Need persisted config + examples
  • Want managed deployment
  • Don't need model choice flexibility

Selling Points & Handling Objections

SA field guide for positioning Supervisor API to customers.

🚀 Top Selling Points

1. Any Tool, Anywhere: Custom MCP servers, custom agents, UC functions, Genie, Knowledge Assistant, external services - all as first-class tools. No vendor lock-in on the tool layer.
2. Model Choice: Use Claude, GPT-5, or any model on Foundation Model API. Switch models without changing tools. A/B test models easily.
3. Enterprise Governance: All tool calls flow through AI Gateway - rate limits, guardrails, audit logging. UC governs data access. Per-user auth for external services.
4. Background Mode: Submit long-running agent tasks (up to 30 min) and poll for results. No other platform offers managed async agent execution.
5. Zero Boilerplate: One API call handles the entire agent loop - model calls, tool selection, execution, response synthesis. No LangChain/LlamaIndex framework needed.

⚠ Common Objections & Responses

ObjectionResponse
"We already use LangChain/CrewAI"Supervisor API doesn't replace your framework - it can orchestrate agents built with any framework via the App tool type. Deploy your LangChain agent as an App, register it as a tool.
"It's in Beta"Beta on Databricks means production-ready for many customers. We're iterating fast - Agent Bricks shipped 2 agent types + 13 improvements in 2 months. Supervisor Agent is already GA.
"We need to run agents on AWS/Azure/GCP"Databricks runs on all 3 clouds. External MCP with U2M auth connects to services anywhere. Custom Agent on Apps can proxy to Bedrock/Vertex/Foundry agents.
"What about cost?"You only pay for AI Gateway usage + tool call costs. No per-step DBU charge. Compare: AWS Bedrock Agents charges per step + session. Azure AI Foundry charges per token + orchestration.
"We need observability"Every agent decision traced to Unity Catalog. MLflow integration for evaluation. AI Gateway provides centralized monitoring across all models and tools.
"How is this different from OpenAI Responses API?"Same API surface (OpenResponses compatible), but with Databricks-native tools (Genie, UC Functions, Knowledge Assistant), enterprise governance (AI Gateway), and data proximity (tools run next to your lakehouse).
